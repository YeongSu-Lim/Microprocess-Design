# 실물 보드 검증 이력과 공개 코드의 버전 구분

[README](../README.md) · [현재 소스 검증 및 개선 사항](validation.md) · [아키텍처](architecture.md)

> **근거 범위:** 마이크로프로세서설계실험 개인 최종 보고서 「S32K144 MCU를 활용한 차량 ECU 구현」(10쪽), 결과 발표자료, 사용자가 제공한 보드 동작 영상 및 시험 설명. **당시 시험 펌웨어와 현재 공개 소스의 일치 여부는 미확인**입니다. 이 문서화 작업은 펌웨어 수정이나 추가 보드 시험을 수행하지 않았습니다.

## 개발·동작 검증 기록

| 구분 | 확인된 결과 | 근거와 한계 |
| --- | --- | --- |
| 6자리 클러스터 | 기어 1자리, 속도 3자리, 거리 2자리 순차 표시 | 개인 보고서 pp.3–6, 7-Segment 사진 |
| 기어 전환 | 초기 개발 단계에서 버튼으로 D→R 표시 전환, 속도·거리 152/88 표시 | 개인 보고서 pp.5–6. 초기 값은 **모터 연동 전 더미 데이터** |
| 모터 변수 연동 | 통합 단계에서 더미 속도·거리를 모터 제어 모듈의 공통 변수로 교체 | 개인 보고서 p.6. 실제 차량 센서 측정값이 아닌 교육용 제어 변수 |
| 표시 주기 튜닝 | 초기 0.5ms에서 입력 반응 지연이 나타나 2ms로 조정했다고 기록 | 개인 보고서 pp.4, 6–7. 당시 개발·시험 버전의 결과 |
| 인터럽트 입력 | GPIO 버튼 ISR 및 input_lock 디바운싱 구현 | 개인 보고서 p.7. 응답 지연의 정량 계측은 미확인 |
| 연료 경고등 | 내부 누적 거리 임계값에 따른 경고 LED 구현 | 개인 보고서 p.8 및 발표자료. 경계값의 계측 로그는 없음 |
| 전체 FSM 동작 | 사용자는 실물 보드에서 상태별 동작과 전이를 확인했다고 설명 | 사용자 진술 및 실물 시연 자료. 모든 상태 전이의 로그와 펌웨어 바이너리 해시 미확보 |

**개인 기여:** 클러스터·연료 경고등 직접 구현, 가속 제어 로직 및 통합 참여. 상태머신·모터·조향 전체의 단독 개발로 표현하지 않습니다.

## 서로 다른 펌웨어 버전과 주기

| 근거 | 표시 갱신 | 제어·경고 |
| --- | --- | --- |
| 개인 최종 보고서 개발·시험 이력 | **0.5ms → 2ms**로 조정 | 별도 **10ms** 채널 |
| 현재 공개 GitHub 소스 (40MHz 입력 클럭 가정) | LPIT Ch1 TVAL 2000 → 명목 **0.05ms** | LPIT Ch0 TVAL 400000 → 명목 **10ms** |

현재 코드 설정은 [handler.c](../handler.c) 및 [architecture.md](architecture.md)에 설명되어 있습니다. **보고서의 2ms를 현재 GitHub 설정으로 표시하거나 현재 소스의 0.05ms를 당시 보드 실측으로 설명하지 않습니다.** 채널 분리라는 설계 결정과 후속 표시 주기 튜닝 경험을 구분합니다.

## 보드 시험과 공개 코드 검증의 경계

현재 공개 [state.c](../state.c)의 정적 분석에서는 초기 OFF에서 P로 진입하는 경로가 보이지 않습니다. 보드 정상 동작 기록과 코드의 정적 분석이 다르지만 시험 펌웨어 버전이 불명확하므로 **어느 한쪽을 근거 없이 오류 또는 해결 완료로 단정하지 않습니다.**

실제 PWM 듀티·주파수, ISR 지터·최악 실행시간, ADC 전체 경계 입력, 각 상태의 재현 가능성은 계측 증빙이 없습니다. 실물 동작 영상은 기능 시연 근거이지 전기적 타이밍 정량 검증을 대신하지 않습니다.
